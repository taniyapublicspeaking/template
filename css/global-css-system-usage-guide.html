Global CSS System
Usage Guide

A practical, self-contained reference for the four stylesheet segments: global.css, sections.css, panels.css, and responsive.css. Learn the class patterns, combine modifiers, and copy ready-to-use HTML and CSS examples.

1. System overview

The system separates global design tokens from reusable layout components. Use the base class first, then add any modifiers that fit the design.

global.css
Design tokens, reset, typography, text utilities, and the global container.
sections.css
Full-width section layout, inner container, header, content, footer, and section variants.
panels.css
Glass panel appearance, tint/blur/shape/shadow modifiers, and panel content helpers.
responsive.css
Tablet/mobile adjustments, reduced motion, touch behavior, and focus-visible rules.
Class pattern: component is the base; component__element is a part inside it; component--modifier changes a variant. For example: section-definition section-definition--blue.

2. Recommended file setup

Keep the four CSS files separate and load them in dependency order. global.css defines variables used by the other files, so it must come first.

HTML · stylesheet links
<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>My Website</title>

  <link rel="stylesheet" href="css/global.css">
  <link rel="stylesheet" href="css/sections.css">
  <link rel="stylesheet" href="css/panels.css">
  <link rel="stylesheet" href="css/responsive.css">
</head>
<body>
  <!-- Your page content -->
</body>
</html>
Suggested project structure
project/
├── index.html
├── css/
│   ├── global.css
│   ├── sections.css
│   ├── panels.css
│   └── responsive.css
└── images/
    └── background.jpg
Background image path: in global.css, url("../images/background.jpg") is resolved relative to the CSS file. If your folders differ, update --background-image. If you do not want a page background image, set it to none.

3. Using global.css

global.css establishes the design vocabulary: fonts, type scale, colors, spacing, container widths, borders, shadows, background settings, and glass presets. Prefer changing tokens over repeating literal values throughout component CSS.

Common tokens

TokenPurposeExample use
--navy, --blue, --orangeBrand paletteHeadings, links, accents
--text-base, --text-lgResponsive type sizesBody copy and emphasis
--section-padding-blockDefault vertical section spacingSpace above/below sections
--container, --container-narrow, --container-wideContent width presetsText, standard layouts, wide grids
--radius, --shadowShared shape and depthCards, panels, section surfaces
--glass-*Glass tint, blur, borders and presetsGlass panels and glass sections

Customize tokens safely

CSS · project-level overrides
/* Load this after global.css if you want project-specific tokens. */
:root {
  --navy: #183153;
  --blue: #1d4ed8;
  --section-padding-block: clamp(3.5rem, 8vw, 7rem);
  --radius: 28px;
  --glass-blur: 20px;
}

Token overrides should usually be placed in a small custom stylesheet loaded after global.css. Remember that changing a token can affect every component that references it.

CSS · tune the image overlay in global.css
:root {
  --background-image: url("../images/hero-background.jpg");
  --glass-image-overlay-start: rgba(15, 23, 42, 0.48);
  --glass-image-overlay-end: rgba(15, 23, 42, 0.72);

  --glass-image-size: cover;
  --glass-image-position: center;

Important distinction: section-definition--glass applies a translucent surface and backdrop blur. section-definition--glass-on-image adds the configured image and overlay; it does not itself add the same border/blur treatment as the --glass modifier. Combine them if that is the intended design, and test contrast over the chosen image.

Interactive panel: make the semantics real

The CSS modifier supplies hover/focus styling, but it does not make a generic <div> keyboard-operable. Prefer a link when the entire panel navigates.

HTML · accessible clickable panel
<a class="glass-panel glass-panel--light glass-panel--interactive"
   href="/services">
  <h3 class="glass-panel__title">Explore our services</h3>
  <p class="glass-panel__text">Open the services page to learn more.</p>
</a>
The current .glass-panel--interactive:hover rule changes the background to a light tint, so that hover state may be unsuitable for dark or navy panels. If you use interactive dark panels, add a specific dark hover rule or avoid that combination. Also consider adding text-decoration:none to the anchor if your global styles do not already remove it.

Optional modifier improvement

CSS · prevent the interactive hover from overriding dark variants
.glass-panel--dark.glass-panel--interactive:hover,
.glass-panel--navy.glass-panel--interactive:hover,
.glass-panel--tint-dark.glass-panel--interactive:hover,
.glass-panel--tint-darker.glass-panel--interactive:hover {
  --panel-bg: rgba(15, 23, 42, 0.88);
  --panel-border: rgba(255, 255, 255, 0.28);
  --panel-text: var(--white);
}

9. Responsive and accessibility behavior

responsive.css makes text widths and container gutters smaller on compact screens, changes the section title size, aligns right-aligned section headers to the left on mobile, reduces hover movement on touch devices, and respects reduced-motion preferences.

RuleWhat it changes
max-width: 768pxText width tokens expand to 100%; container gutter becomes 32px.
max-width: 640pxSmaller gutters, tighter header spacing, smaller section title, right headers become left-aligned, pill panel padding is reduced.
prefers-reduced-motion: reduceDisables panel transitions and hover transforms and turns off smooth scrolling.
hover: noneRemoves hover lift on touch-oriented devices.
:focus-visibleShows a visible keyboard focus outline for interactive panels.
Browser fallback: backdrop blur may not be supported everywhere. The translucent background and border should still provide a surface, but check text contrast with blur disabled. Avoid relying on blur alone to separate text from a busy image.

Optional: stronger keyboard affordance

CSS · focus and hover refinements
.glass-panel--interactive {
  display: block;
  text-decoration: none;
}

.glass-panel--interactive:focus-visible {
  outline: 3px solid var(--blue);
  outline-offset: 4px;
}

@media (prefers-reduced-motion: reduce) {
  .glass-panel--interactive:hover {
    transform: none;
  }
}

11. Accessibility checklist

  • Use semantic headings in order and give each meaningful section a clear heading.
  • Keep body text readable; do not depend on blur or translucency to create contrast.
  • Use anchors for navigation and buttons for actions. A CSS hover class alone does not make a card interactive.
  • Keep a visible keyboard focus indicator for links, buttons, and form controls.
  • Respect reduced-motion preferences; the provided responsive stylesheet already disables panel transitions and hover movement.
  • Decorative icons should use aria-hidden="true"; meaningful icons need an accessible text alternative.
  • Test the layout at narrow viewport widths and with browser zoom increased.

12. Troubleshooting and implementation notes

Styles do not appear

  • Check that the file paths in the <link> tags match your project.
  • Load global.css before component stylesheets.
  • Hard-refresh the browser after editing CSS.

Glass effect is not visible

  • backdrop-filter blurs content behind the panel, not the panel's own text.
  • Place the panel over a background with visible detail; a plain background may make blur subtle.
  • Check that the tint is translucent rather than fully opaque and that the browser supports backdrop filtering.

Section content is unexpectedly narrow

The section's inner width is controlled by --section-max-width. Add section-definition--wide or section-definition--full to the section if the layout needs more room.

Conflicting modifiers

Choose one background modifier and one width modifier per component where possible. If you apply competing variants, later or more-specific CSS rules may determine the result. For a unique design, add a named project modifier instead of relying on accidental cascade order.

Potential CSS refinement

Your supplied section-definition--glass-on-image sets the section's background image and text color but does not explicitly set a translucent background or backdrop filter. This is intentional if the goal is a full image-backed section. If you want a glass surface over the image, combine it with section-definition--glass and test the resulting background layering.

Good default workflow: build the section structure first, add one background modifier, tune width and spacing, then add panels and only the modifiers needed for the intended visual result.
