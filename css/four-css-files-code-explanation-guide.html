1. The big picture

The system is organized by responsibility, not by page. Each stylesheet has one job, and the files share design tokens and class conventions.

Foundation

global.css

Defines the design vocabulary: tokens, reset, base typography, utility classes, and the reusable container.

Layout component

sections.css

Defines the full-width section and its inner container, heading, body, and footer areas, plus visual modifiers.

Surface component

panels.css

Defines glass-like cards/panels, including tint, blur, padding, shape, shadow, interaction, and inner text helpers.

Adaptation layer

responsive.css

Adjusts the existing system for tablet/mobile, touch, keyboard focus, and reduced-motion preferences.

Core principle: tokens define values; components define structure; modifiers select variants; responsive rules adapt those choices to the user's device and preferences.

2. Why the load order matters

Load the foundation first, then components, then responsive overrides. That lets component styles use tokens and lets the final stylesheet refine earlier rules at breakpoints.

HTML · stylesheet order
<link rel="stylesheet" href="css/global.css">
<link rel="stylesheet" href="css/sections.css">
<link rel="stylesheet" href="css/panels.css">
<link rel="stylesheet" href="css/responsive.css">

Remember: load order affects the cascade only when rules have comparable specificity. A highly specific selector in an earlier file can still beat a less specific selector in a later file.

3. global.css — design tokens and defaults

This is the system's foundation. It should contain values that are reused across many components, rather than section-specific styling.

3.1 Design tokens in :root

:root matches the document root. Custom properties declared here are available throughout the page unless overridden on a descendant.

CSS · representative token pattern
:root {
  --font-body: "Inter", sans-serif;
  --color-text: #172033;
  --color-primary: #2459a9;
  --container-max: 1120px;
  --space-section: clamp(3rem, 7vw, 6rem);
  --radius-card: 1rem;
  --shadow-card: 0 12px 32px rgb(10 25 50 / 12%);
}

These names illustrate the pattern. Use the exact token names from your current stylesheet when editing your project.

Token familyWhat it controlsGood reason to edit it
Fonts and type scaleFont families, heading/body sizes, line-heightChange the site's overall typography
PaletteText, brand, surface, and accent colorsApply a global brand refresh
LayoutContainer widths, spacing, guttersMake page content wider or more compact
Shape and depthRadii, borders, shadowsUnify card and panel appearance
Background/glass tokensImages, gradients, overlay, blur and tint defaultsTune background or glass presets centrally

3.2 Reset and base styles

CSS · common reset pattern
*, *::before, *::after {
  box-sizing: border-box;
}

body {
  margin: 0;
  font-family: var(--font-body);
  color: var(--color-text);
}

box-sizing: border-box makes declared widths include padding and borders. Removing the browser's default body margin avoids an unexpected white frame around the page. The actual system may include additional reset rules.

3.3 Typography and utility classes

Global heading, paragraph, link, and text utility rules establish consistent defaults. Utilities such as text alignment or muted text are small single-purpose helpers. Use component classes for component layout; use utilities for small, reusable adjustments.

3.4 The global container

CSS · container concept
.container {
  width: min(100% - 2rem, var(--container-max));
  margin-inline: auto;
}

The container centers content and limits its maximum width. The section itself can remain full-width while its inner content stays readable.

Change here when: you want a site-wide font, color, spacing scale, content width, default radius, or shared shadow to change consistently.

4. sections.css — page structure and section variants

A section is the large horizontal region of a page. The base class establishes shared structure; element classes describe the parts inside it; modifier classes change its visual variant without creating a separate component for every case.

4.1 Read the class naming

HTML · section anatomy
<section class="section-definition section-definition--light section-definition--spacious">
  <div class="section-definition__container">
    <header class="section-definition__header">
      <p class="section-definition__eyebrow">What we do</p>
      <h2 class="section-definition__title">Build with clarity</h2>
      <p class="section-definition__description">A short introduction.</p>
    </header>
    <div class="section-definition__content">...</div>
    <footer class="section-definition__footer">...</footer>
  </div>
</section>
PatternMeaning
.section-definitionBase component; shared section behavior
__containerInner width and horizontal alignment
__headerHeading group layout
__eyebrow, __title, __descriptionSpecific header text roles
__content, __footerMain section content and closing actions
--light, --blue, --spaciousModifier classes that choose a variant

The double underscore convention is commonly used to mark an element belonging to a component; the double hyphen convention marks a modifier. They are naming conventions, not special CSS syntax.

4.2 Base rule versus modifier

CSS · illustrative base and modifier
/* Base: every section gets the shared structure. */
.section-definition {
  position: relative;
  padding-block: var(--section-padding-y, var(--space-section));
}

/* Modifier: one section can choose a different surface. */
.section-definition--light {
  background: var(--section-light-bg, #f4f7fb);
  color: var(--color-text);
}

.section-definition--blue {
  background: var(--section-blue-bg, #2459a9);
  color: #fff;
}

Base rules should hold the default behavior. Modifiers should make a focused change. This avoids duplicating the entire component for each background or spacing option.

5. panels.css — glass panel surface and modifiers

A glass panel is a reusable surface that usually sits inside a section. It controls the panel's own background, blur, padding, shape, shadow, and optional interactive state—not the overall page section layout.

5.1 A base class with optional modifiers

HTML · panel variants
<article class="glass-panel glass-panel--light glass-panel--blur-md glass-panel--rounded">
  <h3 class="glass-panel__title">Clear structure</h3>
  <p class="glass-panel__text">A translucent surface for related content.</p>
</article>

<article class="glass-panel glass-panel--dark glass-panel--blur-lg glass-panel--spacious">
  <h3 class="glass-panel__title">Comfortable reading</h3>
  <p class="glass-panel__text">A darker variation for a contrasting surface.</p>
</article>

5.3 Why backdrop-filter alone may not look like glass

CSS · simplified glass effect
.glass-panel {
  background: rgb(255 255 255 / 18%);
  border: 1px solid rgb(255 255 255 / 28%);
  backdrop-filter: blur(16px);
  -webkit-backdrop-filter: blur(16px);
  border-radius: var(--radius-card, 1rem);
  box-shadow: var(--shadow-card, 0 12px 32px rgb(0 0 0 / 12%));
}

The blur makes pixels behind the panel softer; the translucent background and subtle border help the panel edge remain visible. The effect is easiest to see when there is an image, gradient, or textured surface behind it. Browser support and stacking contexts can affect the result.

5.4 Interactive panels need semantics

If a panel performs an action, make it a real link or button, rather than adding only a pointer cursor. That gives keyboard and assistive-technology users an actionable control.

HTML · clickable panel
<a class="glass-panel glass-panel--interactive" href="/services">
  <h3 class="glass-panel__title">Explore services</h3>
  <p class="glass-panel__text">See how we can help.</p>
</a>
Change here when: the issue is the card's tint, blur, padding, corners, shadow, title/text styling, or hover/focus feel.

6. responsive.css — responsive and accessibility behavior

This file adapts the existing components to different viewports and user preferences. It should refine component behavior, not re-define the entire visual system.

6.1 Breakpoints

CSS · illustrative media query
@media (max-width: 768px) {
  .section-definition {
    padding-block: clamp(2.5rem, 9vw, 4rem);
  }

  .section-definition--align-right .section-definition__header {
    text-align: left;
  }
}

A media query activates its nested rules only when its condition is true. Mobile changes might reduce spacing, adjust heading sizes, stack grids, or align a right-aligned header to the left for easier scanning.

6.2 Reduced motion

CSS · respect user preference
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    scroll-behavior: auto !important;
    animation-duration: .01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: .01ms !important;
  }
}

This is a common pattern for reducing non-essential animation when the operating system indicates that the user prefers less motion. Match it to the project's actual motion policy; avoid suppressing essential status feedback.

6.3 Touch, keyboard, and focus

Touch devices do not have reliable hover. Keep information and actions available without hover, and use focus-visible styling so keyboard users can identify the current control. Responsive styles may also remove excessive hover lift on touch screens.

Accessibility is part of responsive design: test narrow screens, keyboard navigation, contrast, reduced motion, and touch—not only whether the layout fits.

7. Follow one component through the cascade

Consider this class list:

HTML · composition example
<section class="section-definition section-definition--navy section-definition--spacious">
  <div class="section-definition__container">
    <article class="glass-panel glass-panel--light glass-panel--blur-md glass-panel--interactive">
      <h3 class="glass-panel__title">Our approach</h3>
      <p class="glass-panel__text">Purposeful work, clearly explained.</p>
    </article>
  </div>
</section>
  1. global.css supplies fonts, colors, spacing tokens, base typography, and shared container behavior.
  2. sections.css makes the outer region a section, applies the navy surface and spacious vertical padding, and constrains the inner content.
  3. panels.css makes the article a translucent panel with medium blur and interactive states; its title/text helpers style the inner copy.
  4. responsive.css adjusts spacing, text alignment, motion, and interaction details for the current viewport or user preference.
Modifier conflicts: avoid placing two mutually exclusive background modifiers on one element, such as --white and --navy. If both set background, the cascade decides which wins; the result may depend on specificity and source order.

How to think about specificity

When two declarations set the same property, the browser considers importance, origin, cascade layers, specificity, and then source order. Adding more classes can make a rule harder to override. Prefer a clear modifier or token over escalating selectors or scattering !important.

9. Debugging guide

SymptomLikely causeWhat to check
None of the styles appearWrong path or stylesheet not loadedBrowser DevTools → Network; verify the four href paths.
Variables appear invalidToken is missing, misspelled, or declared later on a scopeSearch the exact --token-name in global.css and inspect computed styles.
Background modifier does not winConflicting modifiers or higher specificityInspect the computed background declaration and remove contradictory modifiers.
Glass effect is barely visibleBackground behind panel is flat; tint is too opaque; browser limitationTry a contrasting background, tune tint, and check backdrop-filter support.
Panel content is too wideOuter section container or width modifier is missingInspect section-definition__container and the width variant.
Mobile spacing still feels largeResponsive rule is not matching or overriddenCheck the breakpoint, stylesheet order, and computed padding.
Hover works but keyboard focus is unclearFocus styles are missing or removedTab through links/buttons and add visible :focus-visible styles.

Use DevTools methodically

  1. Inspect the element that looks wrong.
  2. Find the computed property (for example, padding, background, or backdrop-filter).
  3. Identify the winning declaration and its source file.
  4. Change the token if it is a system-wide value; change the component rule if it is component behavior; change the responsive rule if it only fails at a breakpoint.

10. Implementation checklist

  • Keep each stylesheet focused on its responsibility.
  • Load global.css first and responsive.css last.
  • Use tokens for repeated values rather than scattering hard-coded values.
  • Keep component base classes useful without requiring a modifier.
  • Use modifiers for intentional variants and avoid contradictory combinations.
  • Use section modifiers for section-level choices and panel modifiers for panel-level choices.
  • Use real links/buttons for interactive elements.
  • Test glass effects over realistic backgrounds and on supported browsers.
  • Test at mobile widths, with keyboard navigation, and with reduced motion enabled.
  • Use the actual token and class names from the project's source files; code excerpts in this guide explain the patterns and are not a replacement for the complete source CSS.
Rule of thumb: If the change should affect the whole site, start in global.css. If it changes the full-width content region, use sections.css. If it changes a glass card, use panels.css. If it should happen only for a viewport or user preference, use responsive.css.
