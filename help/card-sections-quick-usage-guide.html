How to Use Reusable Card Sections

Learn how to add cards, control the number of columns, use icon or image areas, and choose different layouts for different sections—all while keeping your site’s design consistent.

Core idea: use one base card component, then change its layout with CSS variables and optional modifier classes.

1. The basic idea

A card section has three parts: the section wrapper, a grid container, and one card element for each item.

<section class="card-section">
  <div class="container">
    <header class="section-header">
      <h2>Our Features</h2>
      <p>A short introduction to this section.</p>
    </header>

    <div class="card-grid">
      <article class="single-card">
        <h3>Feature One</h3>
        <p>A short description.</p>
        <a href="#">Learn more →</a>
      </article>
    </div>
  </div>
</section>

The .card-grid arranges cards into columns. Each .single-card is one item. You can add or remove card elements without changing the grid structure.

Remember: CSS controls the layout, not the total number of cards. To show eight cards, include eight card elements—or generate them with JavaScript or a template system.

2. Set global card settings

Put the defaults in the existing :root block in your global.css. Add these variables alongside your current design tokens; do not create a second :root block unless you prefer to keep the settings separated.

:root {
  /* Card layout defaults */
  --card-columns: 3;
  --card-gap: 1.5rem;
  --card-padding: 1.5rem;
  --card-min-width: 240px;
}
VariablePurposeExample
--card-columnsDefault number of columns on wide screens.3
--card-gapSpace between cards.1rem
--card-paddingSpace inside each card.1.25rem
--card-min-widthMinimum width for the auto-fit option.240px

Keep using your existing tokens such as --blue, --navy, --border, --radius, --shadow, --font-heading, and --font-body for visual consistency.

3. Add more cards

Copy one <article class="single-card">...</article> block for each additional card. Change the title, description, icon/image, and link as needed.

<div class="card-grid">
  <article class="single-card">
    <h3>Feature One</h3>
    <p>Description for feature one.</p>
    <a href="/feature-one">Learn more →</a>
  </article>

  <article class="single-card">
    <h3>Feature Two</h3>
    <p>Description for feature two.</p>
    <a href="/feature-two">Learn more →</a>
  </article>

  <!-- Copy another article block to add a third, fourth, etc. -->
</div>

When there are more cards than fit in one row, CSS Grid automatically wraps the extra cards onto additional rows.

4. Set the number of columns

Use the global --card-columns value to set the default desktop layout.

:root {
  --card-columns: 4; /* Four cards per row on wide screens */
}

.card-grid {
  display: grid;
  grid-template-columns: repeat(
    var(--card-columns),
    minmax(0, 1fr)
  );
  gap: var(--card-gap);
}

5. Give each section its own layout

Keep a global default, then use modifier classes when a particular section needs two, three, or four columns.

/* Default layout */
.card-grid {
  grid-template-columns: repeat(
    var(--card-columns),
    minmax(0, 1fr)
  );
}

/* Per-section settings */
.card-section--two   .card-grid { --card-columns: 2; }
.card-section--three .card-grid { --card-columns: 3; }
.card-section--four  .card-grid { --card-columns: 4; }

Choose the layout in the section's class list:

<section class="card-section card-section--four">
  <div class="container">
    <div class="card-grid">
      <!-- Put your card elements here -->
    </div>
  </div>
</section>

Tip: the modifier sets a layout preference; responsive rules can still reduce the number of columns on smaller screens.

6. Use an icon or image area

The same card content can include an icon or image. Use a modifier class to identify the variation, and keep the same base card class.

Icon card

<article class="single-card single-card--icon">
  <div class="single-card-visual">
    <span class="single-card-icon" aria-hidden="true">★</span>
  </div>
  <div class="single-card-content">
    <h3>Our Services</h3>
    <p>Explore the services we offer.</p>
    <a href="/services">Learn more →</a>
  </div>
</article>

Image card

<article class="single-card single-card--image">
  <div class="single-card-visual">
    <img
      class="single-card-image"
      src="images/services.jpg"
      alt="Our team working together"
      loading="lazy"
    >
  </div>
  <div class="single-card-content">
    <h3>Our Services</h3>
    <p>Discover how we can help.</p>
    <a href="/services">Learn more →</a>
  </div>
</article>

For a text-only card, omit the visual block or use a single-card--text modifier if your CSS is written to hide it. Use descriptive alt text for meaningful images, and alt="" for decorative images.

7. Make the grid responsive

A four-column desktop grid is usually too cramped on a phone. Use breakpoints to reduce the columns as the available space gets smaller.

/* Wide screens: use the configured default */
.card-grid {
  grid-template-columns: repeat(
    var(--card-columns),
    minmax(0, 1fr)
  );
}

/* Tablet */
@media (max-width: 900px) {
  .card-grid {
    grid-template-columns: repeat(2, minmax(0, 1fr));
  }
}

/* Mobile */
@media (max-width: 560px) {
  .card-grid {
    grid-template-columns: 1fr;
  }
}
  • Desktop: uses the global or section-specific column count.
  • Tablet: displays two columns.
  • Mobile: displays one column for comfortable reading.

Adjust the breakpoint values to suit the actual width and content of your cards.

8. Optional: let CSS choose the column count

If you prefer columns to adjust automatically according to available space, use auto-fit and minmax() instead of a fixed column count.

.card-grid--auto {
  display: grid;
  grid-template-columns: repeat(
    auto-fit,
    minmax(min(100%, var(--card-min-width)), 1fr)
  );
  gap: var(--card-gap);
}

Choose one strategy per grid: use fixed --card-columns when you want an exact number of columns, or auto-fit when you want the browser to choose based on space.

9. Common issues and fixes

IssueLikely causeWhat to check
Changing the variable has no effect.A more specific CSS rule or media query overrides it.Inspect the computed grid-template-columns in browser developer tools.
Cards look too narrow.Too many columns for the section width.Reduce the column count, gap, or card padding.
Cards do not appear.The card HTML is missing or malformed.Make sure every card is inside the correct .card-grid.
Images look stretched.The image lacks sizing/cropping rules.Use width: 100%, a suitable aspect-ratio, and object-fit: cover.
Every section has the same columns.No section modifier is applied, or the selector is incorrect.Check classes such as card-section--two on the section element.
Font looks different offline.Web fonts could not load.System fallbacks are used; host fonts locally if offline consistency is required.

10. Quick checklist

  • Add card variables to the existing :root block in global.css.
  • Use one .card-grid around the card elements in each section.
  • Use .single-card for the shared card foundation.
  • Add one card element per item you want to show.
  • Change --card-columns for the global desktop default.
  • Use section modifiers when different sections need different column counts.
  • Use icon/image modifiers only where those visuals are needed.
  • Test desktop, tablet, and mobile widths.
  • Use JavaScript or a template system only if you want cards generated from data automatically.

Keep the responsibility clear: CSS variables control appearance and layout. HTML supplies the cards. JavaScript or server-side templates can generate cards from data when you need that extra automation.
